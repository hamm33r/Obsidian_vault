## 一、虚拟存储器的本质：逻辑抽象，非物理存在

### 1. **不存在独立的物理硬件**

- 虚拟存储器**没有对应的物理芯片或存储介质**，它既不是内存条的一部分，也不是硬盘上的某个固定区域。
- 其核心是操作系统通过**软硬件协同**构建的**地址映射逻辑**，使程序“认为”自己独占一个大容量连续内存空间。

### 2. **依赖三大关键组件实现功能**

- **页表（Page Table）**：  
    存放在**物理内存中**的数据结构，记录虚拟页与物理页的映射关系（含存在位、权限位等）。它是地址转换的**核心依据**，但**仅是虚拟存储器的组成部分之一**。
- **内存管理单元（MMU）**：  
    CPU内置的**硬件模块**，负责将虚拟地址实时转换为物理地址。若页表中无有效映射（如页面未加载），会触发**缺页中断**。
- **磁盘交换空间（Swap Space）**：  
    硬盘上划分的特定区域（如Windows的页面文件、Linux的swap分区），用于**暂存未活跃的内存页**。当物理内存不足时，操作系统将部分页面“换出”至此。
表中**需要记录的虚拟页总数**（即页表项总数）**确实远多于主存中实际存在的物理页框数量**，但**实际有效映射的页表项数量**（即已分配物理页框的虚拟页）**不会超过物理内存的总页框数**。关键在于区分 **“页表需覆盖的虚拟页范围”** 与 **“实际映射到物理内存的页数量”**：

## 页表理论容量
1. **页表需覆盖整个虚拟地址空间**，因此其**理论最大表项数 = 虚拟地址空间大小 / 页大小**（如32位系统为2^10=1048576项）。
2. **主存中的物理页框总数 = 物理内存大小 / 页大小**（如4GB物理内存对应1048576个页框）。
3. **实际有效映射的页表项数量 ≤ 物理页框总数**，因为：
    - 一个物理页框**只能被一个虚拟页映射**（同一时刻）；
    - 未分配或换出到磁盘的虚拟页**不占用物理页框**。

| 指标         | 计算方式                       | 32位系统示例（页大小=4KB）    |
| ---------- | -------------------------- | ------------------- |
| 虚拟地址空间大小   | 2^32 = 4GB                 | 4GB                 |
| 虚拟页总数      | 4GB / 4KB = 2^20 = 1048576 | 1048576个            |
| 物理内存大小     | 由硬件决定（如4GB）                | 4GB                 |
| 物理页框总数     | 4GB / 4KB = 1048576        | 1048576个            |
| 实际有效映射的页表项 | ≤ 物理页框总数                   | ≤ 1048576个（通常远小于此值） |

### 1. 常规存储管理方式的特征

- **一次性**：作业在运行前必须一次性地全部装入内存后方能开始运行。
- **驻留性**：作业装入内存后，便一直驻留在内存中，直至作业运行结束。

### 2. 局部性原理

- **时间局部性**：如果程序中的某条指令一旦执行，则不久以后该指令可能再次执行；如果某个数据被访问，则不久以后该数据可能被再次访问。
    - _典型原因_：程序中存在着大量的循环操作。
- **空间局部性**：一旦程序访问了某个存储单元，则不久以后，其附近的存储单元也将被访问，即程序在一段时间内所访问的地址，可能集中在一定的范围内。
    - _典型情况_：程序的顺序执行。

> **笔记重点**：在某一段时间内只会频繁访问一小部分数据和指令。

#### 虚拟存储器的定义及特征

**1. 定义**  
具有**请求调入功能**和**置换功能**、能从逻辑上对内存容量加以扩充的存储器系统称为虚拟存储器。

**2. 特征**

- **多次性**：将一个作业分成多次调入内存。
    - _注_：**多次性**是虚拟存储器**最重要**的特征。
- **对换性**：虚拟存储器允许将那些暂不使用的程序或数据从内存调至对换区，待以后需要时再调入内存。
- **虚拟性**：虚拟存储器对内存的扩充是逻辑上的，用户所看到的大容量只是一种感觉，并不实际存在，因此是虚拟的。**虚拟性**是实现虚拟存储器的目标。
